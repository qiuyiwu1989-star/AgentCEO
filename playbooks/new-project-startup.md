# Playbook: 新项目启动

> 当用户提出新项目、新产品、新方向、新业务时，按此流程执行。

---

## 触发信号

- 用户说"启动一个新项目""我们来做XX""这个方向可以立项"
- 有新目标、新方向、新产品、新客户需求
- 需要多人或多 Agent 协作
- 需要明确里程碑和交付物

---

## 执行流程

### 第一步：识别项目类型

判断属于以下哪种：
- 战略项目（方向性探索）
- 产品项目（具体产品建设）
- 客户项目（外部交付）
- 内容项目（内容生产）
- 能力建设项目（Skill/Agent/知识库）
- Agent 建设项目（新角色）

### 第二步：澄清目标

使用目标澄清模板，确认：
- 最终要达成什么？
- 成功标准是什么？
- 时间边界是什么？
- 资源边界是什么？

**目标不清时，不进入下一步。**

### 第三步：判断战略价值

回答战略五问：
1. 这件事解决什么真实问题？
2. 是否符合组织长期方向？
3. 组织是否具备关键能力？
4. 需要消耗什么资源？
5. 做完后能沉淀什么？

### 第四步：识别关键假设

列出项目成立的前提条件：
- 需求假设：用户真的需要这个吗？
- 价值假设：这能产生足够价值吗？
- 能力假设：我们有能力做到吗？
- 商业假设：这能持续吗？
- 交付假设：我们能按时交付吗？

### 第五步：设计最小验证

用最低成本验证关键假设：
- 验证对象是什么？
- 需要多长时间？
- 通过标准是什么？
- 不通过怎么办？

### 第六步：拆解任务

使用任务拆解模板，产出：
- 任务清单（含负责人、交付物、截止时间、验收标准）
- 关键路径
- 并行任务
- 检查节点

### 第七步：分配角色

明确：
- 人类负责人
- 范德职责
- 相关 Agent
- 相关 Skill
- 外部资源
- 最终验收人

### 第八步：识别风险

列出：
- 战略风险
- 资源风险
- 执行风险
- 能力风险
- 客户风险
- 法律/品牌/数据风险

### 第九步：设置复盘要求

预设：
- 是否需要复盘
- 复盘时间
- 应沉淀为什么（方法/流程/模板/Skill/Agent/案例/风险规则）

---

## 输出模板

```
【新项目启动方案】

项目名称：
项目类型：
核心目标：
成功标准：
关键假设：
最小验证：
关键交付物：1. 2. 3.
任务拆解：第一阶段：… 第二阶段：…
角色分工：人类负责人：/ 范德职责：/ 相关 Agent：
时间节点：启动时间：/ 检查节点：/ 复盘时间：
主要风险：战略：/ 资源：/ 执行：
需要人类确认：1. 2. 3.
下一步：立即启动的三件事
```

---

## 升级条件

涉及以下情况必须升级给人类：
- 重大资源投入
- 客户承诺
- 战略方向变化
- 品牌发布
- 法律/财务/人事/数据风险
- 关键目标无法明确
- 项目是否值得做存在重大不确定
