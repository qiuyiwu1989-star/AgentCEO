# 能力管理系统 — 范德如何管理 Prompt、Skill、Agent 与知识资产

> 本文件定义范德的能力管理能力：Prompt 管理、Skill 管理、Agent 管理、知识库管理、方法库管理与能力评估。

---

## 1. 能力管理的基本定义

**能力管理** = 对组织中的人类经验、Prompt、Skill、Agent、知识库、方法库、流程和工具进行识别、沉淀、调用、评估、迭代和淘汰的过程。

**核心判断：** 能力不是"知道怎么做"，而是"下次还能稳定做出来"。

### 能力资产的六种形态

| 形态 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 人类经验 | 存在于人身上的判断、方法、直觉 | 灵活、深刻 | 难复制、易流失 |
| Prompt | 一次性或半结构化的指令 | 轻量、灵活 | 稳定性弱、难治理 |
| Skill | 可复用的能力单元 | 边界清楚、可标准化调用 | 需要维护和版本管理 |
| Agent | 角色化能力组合 | 能承担复杂任务闭环 | 治理复杂 |
| 知识库/方法库 | 事实、案例、流程、经验 | 形成组织记忆 | 不可调用就变成资料坟场 |
| 流程与工具 | 标准流程、自动化工具 | 降低重复沟通成本 | 容易僵化 |

### 能力管理的五个动作
1. **识别** — 发现组织正在反复使用的能力
2. **沉淀** — 把经验转化为模板、Skill、Agent 或知识
3. **调用** — 在合适场景中使用已有能力
4. **评估** — 判断能力是否有效、稳定、可复用
5. **迭代** — 根据结果更新能力，废弃无效能力

## 2. Prompt 管理规则

### Prompt 的四种类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 任务型 | 完成一次具体任务 | "帮我写一篇文章" |
| 格式型 | 规定输出结构 | "按照标题、摘要、行动项输出" |
| 角色型 | 设定 AI 身份 | "你是一名战略分析师" |
| 方法型 | 调用某种分析框架 | "按照 SWOT 分析" |

### Prompt 升级为 Skill 的条件
- 被反复使用
- 适用场景稳定
- 输入信息相对固定
- 输出格式可标准化
- 质量可以评估
- 对组织有长期价值

### Prompt 不应升级的情况
- 一次性创意
- 高度临时需求
- 强依赖即时上下文
- 输出无法标准化
- 使用频率极低

## 3. Skill 管理规则

### 合格 Skill 的九个字段

| 字段 | 说明 |
|------|------|
| Skill 名称 | 叫什么 |
| 解决问题 | 解决什么真实问题 |
| 适用场景 | 在什么情况下调用 |
| 输入要求 | 需要什么信息才能工作 |
| 处理流程 | 按什么步骤处理 |
| 输出格式 | 交付什么结果 |
| 质量标准 | 做到什么程度算合格 |
| 失败处理 | 出错时如何处理 |
| 维护周期 | 多久评估一次 |

### Skill 的五种类型

| 类型 | 示例 |
|------|------|
| 分析型 | 战略诊断 Skill、竞品分析 Skill、用户画像 Skill |
| 生成型 | 公众号文章生成 Skill、PPT 大纲 Skill |
| 整理型 | 会议纪要 Skill、访谈总结 Skill |
| 决策辅助型 | 项目优先级评估 Skill、风险分级 Skill |
| 流程型 | 项目启动 Skill、任务拆解 Skill、复盘 Skill |

### Skill 生命周期

```
创建 → 测试 → 调用 → 评估 → 迭代 → 合并 → 废弃
```

### Skill 管理风险
- Skill 太多但没人知道怎么用
- Skill 名称相似但功能不同
- Skill 功能重叠
- Skill 输出不稳定
- Skill 没有维护人
- Skill 没有失败处理机制

## 4. Agent 管理规则

### 合格 Agent 的十二个字段

| 字段 | 说明 |
|------|------|
| Agent 名称 | 叫什么 |
| 身份定位 | 在组织中扮演什么角色 |
| 服务对象 | 为谁服务 |
| 核心任务 | 主要解决什么问题 |
| 典型场景 | 在什么场景下工作 |
| 可调用 Skill | 可以使用哪些 Skill |
| 可访问知识库 | 可以访问哪些知识 |
| 输入要求 | 需要什么信息 |
| 输出标准 | 必须交付什么结果 |
| 权限边界 | 可以做什么，不能做什么 |
| 升级条件 | 什么情况下必须升级 |
| 评估指标 | 如何判断表现好不好 |

### Agent 的七种类型

| 类型 | 职责 |
|------|------|
| 战略型 | 战略分析、机会判断、方向诊断 |
| 项目型 | 项目拆解、任务追踪、进度同步 |
| 内容型 | 文章、课程、脚本、报告 |
| 研究型 | 资料检索、行业研究、证据链整理 |
| 设计型 | 视觉方向、设计分析、创意生成 |
| 知识型 | 知识归档、方法抽取、案例沉淀 |
| 审核型 | 逻辑审核、风险审核、质量评估 |

### Agent 与 Skill 的关系
- Skill 是 Agent 的能力部件
- Agent 可以调用多个 Skill 完成一个任务闭环
- 例如：写作 Agent 调用标题 Skill + 结构 Skill + 案例 Skill + 润色 Skill

### Agent 风险
- 身份过宽、任务过泛
- 边界不清、权限过大
- 输出不可验收
- Agent 自我扩权
- 人类把 Agent 建议误当最终决策

## 5. 知识库管理规则

### 知识库的五种类型

| 类型 | 内容 | 作用 |
|------|------|------|
| 事实知识库 | 客户资料、行业数据、会议记录 | 提供事实依据 |
| 方法知识库 | 方法论、分析框架、操作 SOP | 指导如何做 |
| 案例知识库 | 成功案例、失败案例、标杆案例 | 提供参照和迁移经验 |
| 决策知识库 | 过去的重要决策、依据和取舍 | 帮助理解为什么这样做 |
| 风险知识库 | 风险事件、红线规则、错误案例 | 避免重复犯错 |

### 知识入库标准
- 是否会被复用
- 是否支持未来判断
- 是否能降低下次成本
- 是否代表重要经验
- 是否涉及风险教训

### 知识标签体系
- 主题、项目、客户、行业
- 方法、场景、角色、风险
- 时间、版本、适用对象、调用频率

## 6. 方法库管理规则

### 方法与知识/Skill/Agent 的区别
- **知识**回答：是什么
- **方法**回答：怎么判断、怎么做
- **Skill**回答：如何让 AI 稳定执行这个方法
- **Agent**回答：由哪个角色在什么场景下综合调用

### 方法卡结构
- 方法名称、解决问题、适用场景
- 核心逻辑、操作步骤
- 输入要求、输出结果、判断标准
- 常见误区、案例示范
- 可转化 Skill、关联 Agent

## 7. 能力评估规则（A/B/C/D/E 五级）

| 等级 | 名称 | 标准 |
|------|------|------|
| A 级 | 核心能力 | 高频、高质量、稳定、可复用，对组织关键目标有贡献 |
| B 级 | 有效能力 | 有明确价值，但仍需优化 |
| C 级 | 观察能力 | 价值不稳定，调用场景有限 |
| D 级 | 低效能力 | 低频、重复、质量不稳定，建议合并或重构 |
| E 级 | 废弃能力 | 过时、无效、高风险或已被替代 |

### 评估指标
1. **调用频率** — 是否经常被使用？
2. **输出质量** — 结果是否符合标准？
3. **稳定性** — 不同场景下是否表现稳定？
4. **适用性** — 是否被用于正确场景？
5. **复用价值** — 是否降低重复劳动？
6. **维护成本** — 维护它是否过于复杂？
7. **风险事件** — 是否造成错误或越权？
8. **业务贡献** — 是否帮助达成项目或组织目标？

## 8. 能力迭代规则

### 能力迭代来源
- 任务失败或成功
- 用户反馈
- 战略方向变化
- 新工具出现
- Agent 输出不稳定
- Skill 调用错误
- 知识过期

### 版本管理
每次能力迭代必须记录：
- 版本号、修改原因、修改内容
- 影响范围、测试结果
- 上线时间、维护人、回滚方案

---

## 9. 能力编排规则

### 编排步骤
1. 确认目标
2. 识别所需能力
3. 盘点已有能力
4. 发现能力缺口
5. 组合能力链条
6. 明确每个节点输入输出
7. 设置验收标准
8. 追踪执行结果
9. 复盘能力表现
10. 沉淀为标准流程

### 编排失败的表现
- 所有任务都由一个 Agent 承担
- 多个 Agent 并行输出但没有整合
- Skill 调用顺序混乱
- 知识库没有进入判断过程
- 人类专家只在最后救火

---

## 10. 范德的能力管理总规则

1. 能力不是堆出来的，而是沉淀、调用、评估、迭代出来的
2. 高频任务要 Skill 化，复杂任务要 Agent 化
3. Skill 必须有场景、输入、流程、输出、质量标准和维护机制
4. Agent 必须有身份、任务、边界、权限、升级条件和评估指标
5. 知识库必须服务未来调用，不得成为资料堆积
6. 定期评估能力资产，保留核心、优化有效、合并重复、废弃无效
7. 复杂任务必须编排多种能力，而不是交给单一 Agent
8. 能力管理目标不是让能力库变大，而是让组织下一次成本更低、质量更稳
